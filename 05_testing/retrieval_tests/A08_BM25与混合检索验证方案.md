# A08 BM25 与混合检索验证方案

版本 A-v0.1｜2026-11-05｜作者：组员 A 的 AI 辅助整理，待本人复核｜状态：设计，全部未执行。

## 要解决的问题

EngiMate 的资料可能同时含项目编号、器件型号和自然语言要求。词法检索有机会较好处理精确词项，向量检索有机会处理改写和近义表达；二者的实际表现取决于分词、语料、分块、模型和配置，必须比较。多文件、多项目场景还需要版本管理、项目边界和权限控制，不能只依赖检索算法。

L5 PDF 第 25—28 页分别介绍 embedding 与 BM25，第 29 页给出初始检索、reranking、top-k 的流程。Lab 3 PDF 第 6 页截图出现 `Vector search`，但截图不证明用户能够选择 BM25、混合检索、权重、RRF 或 reranker，也不代表当前界面相同。学校[知识库公开指南](https://knowledgebase.xjtlu.edu.cn/article/3-basic-features-of-knowledge-base-on-xipu-ai-platform-408.html)介绍管理、测试及连接 Agent，未提供上述算法的明确证据。当前 XIPU AI 算法和具体能力为**待确认**。

## 候选方案和可行性判断

1. 若真实界面或学校文档明确开放并说明：分别记录可选的词法/BM25、向量及混合检索；只有标明 BM25 或官方技术文档确认时才称为 BM25。`Keyword` 输入标签、`Vector search` 按钮或一个分数不单独证明后台算法。
2. 若支持多路检索融合，记录实际方法与权重；例如可用 RRF 根据不同列表的排名融合，但不要假定平台使用 RRF。参考 [Elastic Hybrid Search](https://www.elastic.co/docs/solutions/search/hybrid-search)、[RRF](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion/)。
3. 若仅有现成检索方式，则先用其进行基线测试；可以设计外部 BM25 作为**离线对照实验**，但必须有允许接入的检索工具/API、可验证的调用轨迹和实际测试，才可宣称已经成为 XIPU AI Agent 的检索路径。提示词写“使用 BM25”不会自动创建索引或接入检索器。
4. 若不同模式无法分别选择、不能固定语料/分块或无法观察返回内容，则标注“无法完成受控比较”，记录平台当前可观察的结果；不能推断哪种算法更优。

## 如何公平比较与记录

1. 在平台确实允许选择时，对同一语料、问题、解析/切块、项目范围、返回数量 K 与可见阈值运行每种模式；分别保留原始命中和版本。无法固定的变量全部记下，不能将多个因素造成的差异归因于 BM25。
2. 用**固定粒度**人工评定相关证据。单一事实题记录目标证据在 top-K 中的排名；多文件题单独记录两份必要证据是否都覆盖。不同模式或设置若改变了切块，先建立片段到同一原文证据位置的对应，不能直接把不同片段当作等价样本。
3. 当返回排名、全部已知相关片段和 K 可观察时，可按事先定义计算 `Recall@K = top-K 中相关片段数 / 已知全部相关片段数`；MRR 是每个有答案问题的首个相关片段倒数排名的平均值。相关片段要预先人工标注，不能把 Agent 的回答当标准答案。两份资料都必需的题另外报告“双证据覆盖”，首个相关结果出现不代表答案完整。
4. 无答案题不计算分母为 0 的 Recall；单独检查有无捏造依据及最终答案是否恰当承认缺失。跨项目用例评估回答与范围，不能仅凭一次成功证明权限隔离。
5. 单独评估 Agent 最终答案的依据、完整性和事实性；Hit test 的排名不证明 Agent 同次调用一定收到相同片段。记录端到端延迟和可见开销，不能只比较准确性。8 题只能作功能性初查，数据量不支持总体性能结论；较大规模需在权限允许下构建更多多类型文档和干扰项，再独立人工标注、重复比较。
