# 任务拆解
## 1. 总体目标
本文件为团队方法参考文档，提供工程项目从交付物拆解为可执行任务的方法。指导使用者把笼统的大任务拆分成粒度合适的工作单元，明确产出物、验收条件、前后任务依赖，覆盖需求、设计、开发、采购、集成、测试、报告、演示全流程，适用于硬件、软件以及软硬件结合的课程小组项目。

## 2. 任务拆解核心原则
1. 每个任务要有明确产出，禁止只写“做硬件”“写代码”这类模糊描述。
2. 每条任务必须定义验收条件，用来判断任务是否真正完成。
3. 识别任务前置依赖，前序任务完成之后，才能开展后续任务。
4. 合理控制粒度：单任务预估工时不宜过大；任务过小也会造成管理繁琐。
5. 区分串并行任务，部分工作可以同时开展，受依赖约束的任务必须顺序执行。

## 3. 项目阶段划分
- 需求阶段：梳理项目需求、整理课程要求，确定项目范围与交付物
- 设计阶段：方案设计、架构设计、硬件选型、接口定义
- 采购阶段：元器件、物料、软件资源准备
- 开发阶段：硬件制作、代码编写、功能实现
- 集成阶段：把各个独立模块组合到一起
- 测试阶段：功能测试、问题调试、缺陷修复
- 文档报告阶段：撰写项目报告、整理过程资料
- 演示准备阶段：准备演示流程、答辩素材

## 4. 模糊任务改写示例
> 将笼统描述改写为带产出、验收条件的规范任务，共3组对照示例

### 示例1
❌模糊任务：完成软件功能开发
✅改写后
- 任务：完成核心业务逻辑代码开发
  产出：可运行程序源码
  验收条件：核心业务逻辑可以正常运行，无阻断性报错

### 示例2
❌模糊任务：采购项目元器件
✅改写后
- 任务：完成项目所需物料采购核对
  产出：物料清单、到货核对记录
  验收条件：全部清单内物料到货，元器件型号与设计选型保持一致

### 示例3
❌模糊任务：做项目测试
✅改写后
- 任务：开展整体集成功能测试
  产出：测试记录文档，缺陷清单
  验收条件：执行全部测试项，记录问题，区分已修复和待修复缺陷

## 5. 任务字段说明
生成任务时，每条任务应当包含以下字段：
- 任务编号
- 任务内容
- 建议负责人
- 产出物
- 验收条件
- 前置依赖
- 预计工时
- 期限
- 任务状态（未开始 / 进行中 / 受阻 / 已完成）

> 无法确定的信息统一标记为【待确认】，不要编造数值。

## 6. 不同类型项目拆解提示
1. **纯软件项目**：重点关注架构设计、模块开发、接口联调、单元测试、文档编写；无硬件采购任务。
2. **纯硬件项目**：重点关注选型、采购、加工焊接、硬件调试；软件相关任务可以删减。
3. **软硬件结合项目**：需要重视软硬件接口定义，硬件到货会成为软件调试的前置依赖，需要预留调试缓冲时间。
