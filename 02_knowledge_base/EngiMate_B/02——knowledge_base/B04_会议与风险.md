# 会议与风险管理
## 1. 文档目的
提供会议信息整理规范以及项目风险识别、评估、处置的方法。用于小组开完会议之后提取关键决议、行动项；提前识别项目里面潜在风险，制定应对方案，降低项目失败、延期的可能性。

## 2. 会议记录规范
会议记录必须区分四类信息：正式决定、讨论建议、行动项、待解决问题
1. **正式决定**：小组已经达成共识、确定下来的内容，后续项目执行以此为准。
2. **讨论建议**：会上提出的想法，尚未表决通过，仅作为参考，不能直接落地执行。
3. **行动项**：需要人员去完成的具体工作，行动项必须写明：内容、负责人、截止时间。
4. **待解决问题**：本次会议没有得出结论，留到后续讨论的议题。

> 重要提醒：不能单纯把计划表述直接标记成已经完成。

## 3. 风险基础概念
风险 = 发生的可能性 × 造成影响的严重程度
风险发生之后有可能造成工期延后、交付物质量下降、项目无法满足课程要求。

## 4. 风险识别方向
工程项目常见风险维度：
1. 人力风险：组员时间变动、人员退出、工作量过载
2. 时间风险：任务延期、关键节点推迟
3. 技术风险：技术难点无法攻克、方案不可实现
4. 资源风险：物料采购延迟、缺少需要的工具
5. 需求风险：项目范围发生变更、需求理解不一致

## 5. 风险记录字段
每一条风险记录包含：
- 风险编号
- 风险简要描述
- 发生可能性（高 / 中 / 低）
- 影响程度（高 / 中 / 低）
- 风险等级
- 应对预案（预防措施 + 如果真发生之后的补救方案）
- 风险状态：未发生 / 正在发生 / 已关闭

## 6. 风险传导说明
风险会产生连锁传导效应，一处任务阻塞，会顺着依赖链影响后面一系列任务，进行进度检查的时候需要追踪整条传导链。
修改风险对应的处置方案之后，方案依然需要小组确认，助手不能够私自决定变更。
