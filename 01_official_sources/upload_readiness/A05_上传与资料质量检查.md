# A05 上传与资料质量检查

类别：开发检查清单｜版本：A-v0.3｜日期：2026-11-05｜状态：待平台操作和复核。平台步骤依据 ISA104 Lab 3 pp.4–6 与 [XJTLU 公开指南](https://knowledgebase.xjtlu.edu.cn/article/3-basic-features-of-knowledge-base-on-xipu-ai-platform-408.html)；当前界面和权限可能不同。

## 导入前：先确定用途

| 文件类别 | 放置建议 | 不应做的事 |
|---|---|---|
| 通用工程方法 | B 的经审阅方法正文；A03 和 A06 可作为候选，需先解决冲突并选定主版本 | 将 ISA104 本组日期、固定人员或老师规则作为所有用户的默认事实；直接上传相互矛盾的多个版本 |
| 当前项目文件 | 经授权、适用且版本明确的 brief/rubric 和项目记录 | 把另一个项目的要求或用户私有资料混入 |
| 测试资料 | 隔离的测试环境使用 `05_testing/retrieval_tests/fixtures` | 将虚构日期、冲突通知或参考答案放进真实用户知识库 |
| 开发参考 | A01、A02、A05、A07 和测试结果供人审核 | 因文件保存在仓库就默认全部适合上传 |

## 对 B 材料的具体操作

- 仓库当前同时有 `02_knowledge_base/02——knowledge_base/` 和 `02_knowledge_base/EngiMate_B/02——knowledge_base/` 两套 B01—B05；在本次核查的提交中对应文件 SHA 相同。上传前与主搭建人选定**一套**作为审核基线，避免重复召回与未来版本分叉。
- B01 内含 EngiMate 自身目标和范围；B03 第 6 节为本组 A/B/C/D 分工。若作为通用知识，需清楚区分“产品自身说明”和“未来用户的项目角色”，见 [A07](../A07_BC材料交叉核查.md)。
- B07 当前是 Arduino LED 示例，尚不是 C 测试中引用的完整环境监测案例；测试前确认资料版本，不把 A 的测试夹具冒充 B 的案例。

## 建议上传与连接顺序

1. 先由团队选定 B 的一套主版本并处理 A07 所列冲突；A03、A06 是否并入通用正文由主搭建人与 B 确定。不要把仓库的整个目录一次性导入。
2. 导入经确认的通用方法文件，记录文件名、版本和平台处理状态；再导入有权限使用、且适用于**当前项目**的 brief、rubric 或项目记录。ISA104 本组资料只有在当前项目确实为该项目时才适用。
3. 排除来源登记、评审意见、A04 题目及预期答案、测试运行记录和私人信息。A03 的回答示例另在测试目录，不能当作当前项目事实导入；虚构夹具仅供独立测试环境使用。
4. 平台处理后，先检查解析与 Hit test，再连接相同版本到 Agent，记录当前平台实际可见的配置并运行对应测试。若界面没有某项功能，记录为待确认，不臆造操作路径。

## 每份文件的检查

1. 确认来源、文件类别、适用项目、版本、作者或维护人；不明时标待确认。
2. 人工打开，检查可复制文字、表格表头、条件、单位、日期及必要脚注。扫描件或图片中的文字需要额外核对。
3. 删除不必要的密码、身份信息、真实私人聊天记录和无授权内容；引用时记录原始文件和位置。
4. 等待平台处理完成；处理完成不等于内容全部解析正确。
5. 根据 Lab 3 先使用 Auto chunking；检查实际界面显示的片段，不凭经验给出通用最优块长。
6. 用固定问题分别记录 Hit test 命中片段、来源与完整 Agent 答案。Hit test 与 Agent 调用可能不同，需核对连接、版本和可见轨迹。
7. 保存设置、输入、原始输出和问题记录；未执行测试保持“未执行”。

## 权限与已知未知

当前尚未验证平台的每次会话文件读取、多用户授权、项目隔离、引用定位、更新重索引和长期记忆。只有实际配置、调用、读取与权限检查成功，才能向用户描述相应能力；提示词和项目编号不能替代访问控制。
