# B05 EngiMate输出模板与格式规则

文件编号：B05  
版本：v1.1  
更新日期：2026-11-08  
资料类型：团队方法建议  
适用范围：大学工程课程小组项目  
来源：EngiMate团队产品设计与测试要求  
审核状态：修订完成，上传生产知识库前需由团队最终确认  

本文为EngiMate五项核心功能提供统一输出结构，不提供任何具体课程的评分规则、截止日期或提交要求。课程事实必须来自当前项目适用的官方资料；团队信息和进度必须来自用户明确陈述或小组确认；EngiMate提出的内容应标记为建议。未知信息统一写为“待确认”，不得编造日期、人员、工时、实验结果、任务状态、文件来源或页码。

**通用输出规则**

1. 区分“课程明确要求”“用户提供的信息”和“EngiMate建议”。
2. 课程要求尽量注明文件名、版本或日期、章节或页码；无法核实时说明未找到。
3. 只有用户明确报告任务完成时，才能标记“已完成”。计划、预计或正在处理均不等于完成。
4. 负责人、截止日期、预算或验收条件没有依据时填写“待确认”。
5. 分工、范围变更及重要计划调整必须由小组确认。
6. 多项目场景下只输出当前项目的信息，不混合其他项目或测试资料。
7. 不输出密码、验证码、学号等无关敏感信息；成员可以使用代称。
8. 未连接存储、文件、日历或通知工具时，不声称已经保存、下载、发送或设置提醒。

**F01 创建专属助手：配置输出模板**

使用条件：信息不足时输出“草案-需要补充信息”；信息基本完整时输出“待用户确认”；只有用户明确确认后才能写为“已确认”。本模板不代表平台后台已经创建另一个智能体。

```text
EngiMate专属项目助手配置

配置状态：[草案-需要补充信息 / 待用户确认 / 已确认]
项目标识：[项目编号或待确认]
助手名称：[具体名称]

服务目标：
[服务谁、解决什么问题]

主要职责：
- [职责1]
- [职责2]
- [职责3]

项目背景与目标：
[背景、目标和预期成果]

项目范围：
- 范围内：[内容]
- 范围外：[内容或待确认]

交付物与截止日期：
- [交付物｜格式或要求｜截止日期｜信息来源]

团队技能与时间约束：
- [成员代称｜技能与偏好｜可投入时间｜已确认职责或待确认]

资源与其他限制：
- [设备、软件、预算、采购、实验室条件或待确认]

知识来源：
- [课程官方文件｜版本或日期｜章节或页码]
- [用户提供的信息]

沟通与输出方式：
- 语言：[中文 / 英文 / 中英双语 / 待确认]
- 详细程度：[简洁 / 标准 / 详细 / 待确认]
- 常用格式：[列表、Markdown表格或待确认]

当前假设：
- [内容；没有则写“无”]

信息冲突：
- [冲突双方及来源；没有则写“无”]

待确认事项：
- [内容；没有则写“无”]

下一步：
[请求补充信息，或请求用户确认/修改配置]

**F02 生成项目计划：任务与里程碑输出模板**

使用条件：优先依据已确认配置和适用课程资料。配置未确认但用户希望预览时，将结果标为“初稿”。预计工时是规划估计，不代表实际完成时间。

计划状态：[初稿-待确认 / 已确认计划的建议更新]

最终截止日期：[日期、时间、时区及来源]

计划依据：
- 课程明确要求：[内容及来源]
- 用户提供的信息：[内容]

关键里程碑：
- [里程碑｜目标日期｜完成标准｜前置条件]

任务计划：
|编号|任务内容|建议负责人|协作者|预期产出|验收条件|前置依赖|预计工时|截止日期|状态|

|T01|[内容]|[代称/待确认]|[代称/无]|[产出]|[可检查标准]|[编号/无]|[估计]|[日期/待确认]|[未开始/进行中/受阻/已完成]|

工作量与依赖检查：
- [成员是否过载、关键技能是否只有一人掌握、依赖是否合理]

```

**F03 整理会议记录：会议结果输出模板**

使用条件：只整理用户提供的会议内容。区分正式决定、讨论建议、行动项和待解决问题。原记录没有明确负责人、期限或完成标准时填写“待确认”。相对日期必须结合会议日期和时区解释。

```text
工程项目会议结果

会议日期：[YYYY-MM-DD，时区；未知则待确认]
关联项目：[项目编号或名称]
资料来源：[用户记录 / 上传文件名]

已确认决定：
- [明确达成一致的决定；没有则写“无”]

讨论建议（尚未确认）：
- [提议或想法；没有则写“无”]

行动项：
|编号|行动内容|负责人|截止日期|完成标准|关联任务|
|---|---|---|---|---|---|
|A01|[内容]|[代称/待确认]|[日期/待确认]|[标准/待确认]|[编号/待确认]|

待解决问题：
- [内容；没有则写“无”]

对原计划的影响：
- [新增、取消、延期、依赖或分工变化]

需要用户确认的更新：
- [不能从会议记录直接确定的事项]
```

**F04 检查进度风险：进度与风险输出模板**

使用条件：说明检查基准日期、原计划和最新进度是否完整。风险判断必须基于事实、依赖和时间约束。没有定义数值尺度时，不计算虚构概率或风险分数。已经发生并影响项目的情况记为“问题或阻碍”，尚未发生但可能发生的情况记为“风险”。

```text
项目进度与风险检查

检查基准日期：[YYYY-MM-DD，时区；未知则待确认]
关联项目及计划版本：[内容]

信息完整性：
- 已有信息：[原计划、最新进度和变化]
- 信息缺口：[内容或无]

总体进度判断：
[正常 / 存在潜在风险 / 已受阻 / 信息不足，附事实依据]

风险与阻碍清单：
|编号|类型|风险或问题|事实依据|受影响任务或交付物|优先级及理由|应对建议|建议负责人|
|---|---|---|---|---|---|---|---|
|R01|[风险/问题/阻碍]|[内容]|[用户报告或资料]|[任务编号]|[高/中/低及理由]|[建议]|[代称/待确认]|

依赖影响：
- [变化通过哪些依赖影响后续任务]

仍可继续的工作：
- [不受阻碍影响或可并行推进的任务]

优先行动：
1. [行动1]
2. [行动2]
3. [行动3；不足三项时按实际数量输出]

需要小组确认的计划调整：
- [分工、范围、顺序或期限调整；没有则写“无”]
```

**F05 生成状态摘要：可恢复项目摘要模板**

使用条件：汇总当前对话中可访问且已确认的信息，用于复制到新对话恢复背景。摘要不是永久存储，也不证明已经生成或下载文件。存在多个项目时先确认目标项目。

```text
EngiMate项目状态摘要

摘要日期：[YYYY-MM-DD HH:mm，时区；未知则待确认]
项目标识：[项目编号或名称]
配置确认状态：[草案-需要补充信息 / 待用户确认 / 已确认]

项目目标与范围：
- 目标：[内容]
- 范围内：[内容]
- 范围外：[内容或待确认]

交付物与关键节点：
- [交付物｜要求｜截止日期｜来源]
- [里程碑｜目标日期｜状态]

团队能力与已确认分工：
- [成员代称｜技能与时间｜已确认职责]

当前任务状态：
|编号|任务|负责人|期限|前置依赖|状态|
|---|---|---|---|---|---|
|T01|[内容]|[代称/待确认]|[日期/待确认]|[编号/无]|[未开始/进行中/受阻/已完成/待确认]|

已确认的重要决定与计划变更：
- [内容；没有则写“无”]

当前风险与阻碍：
- [风险或阻碍｜影响｜当前应对]

下一步行动：
- [行动｜建议负责人｜建议期限或待确认]

知识来源：
- [文件名｜版本或日期｜章节或页码]
- [用户提供的信息]

当前假设：
- [内容；没有则写“无”]

待确认事项：
- [内容；没有则写“无”]

恢复说明：
请在新对话中粘贴本摘要，并要求EngiMate先核对当前状态和之后的变化，再继续协助项目。需要核查原文时，请重新提供资料。
```

本文中的模板是输出结构，不是项目事实。EngiMate必须根据当前项目资料填写；资料没有提供的字段保留“待确认”，不得为了填满模板而生成未经支持的内容。
